# deai-loop — 去 AI 味自循环

## 设计哲学（三条铁律，来自四轮迭代实战）

1. **模型大于提示词**：语感长在生成分配里，改写主体用「装着真人中文语感」的模型（gemini-2.5-flash 实测），提示词只管红线。
2. **检测分 ≠ 对味**：2026-10-03 实测——用户验收过的文章句长 CV 疑似项（8）反而多于被否掉的初稿（5）。统计信号有参考价值但**不是裁判**，循环目标是「收敛 + 人觉得对味」，不是检测分归零。为骗检测器而改写会过拟合出新的怪味。
3. **确定性归脚本，语感归模型，终审归人**：禁语 grep / 数字 diff / 围栏配对用脚本（可复现）；段落怎么改用 Gemini；每一轮的成品必须人过目（配 Before/After 对比）。

## 流程（循环 ≤3 轮）

```
原文 → ① detect.py 统计检测（定位疑似段落）
     → ② LLM 判官（可选强化定位，见下）
     → ③ 段落级重写（只动疑似段落，Gemini）
     → ④ 事实 diff 质检（数字/术语不得变）
     → ⑤ 复检 detect.py → 分数收敛？→ 否则回到 ③（≤3 轮）
     → ⑥ 人终审（强制闸门）+ Before/After 报告
```

### ① 统计检测

```bash
python3 .claude/skills/deai-loop/scripts/detect.py <文章.md> [--json]
```

输出：段落级疑似清单（句长 CV / 禁语 / 加粗 / 全文段落均匀度），退出码 0 干净 / 1 有疑似。

**信号的分层权重（实测校准，2026-10-03）**：
| 信号 | 权重 | 实测依据 |
|---|---|---|
| 禁语 grep | **主信号** | 四轮迭代中每篇必中（「这意味着」Gemini 每篇 2-4 处），修复即改善 |
| 数字/短语加粗 | **主信号** | 生成模型强调习惯，去之无损 |
| 句长 CV（<0.30 均匀段） | 弱信号 | 学术长句文有效（MBA 论文场景验证）；博客短段落体区分度弱（验收稿与退稿无差异）——只用于 Before/After 趋势对比，不单独触发改写 |
| 全文段落均匀度 | 弱信号 | 同上，参考 |

禁语命中要人工豁免两类：引用原话（转述反馈、举例）、讨论该词本身（如本文）。

### ② LLM 判官（可选，定位强化）

统计层抓不到的「腔调」问题（设计感开场、完美闭环、对仗癖）用另一个模型当读者定位。prompt 要点：给全文 + 「你是挑剔的中文博客读者，标出让你觉得像 AI 生成的段落并说明原因」。判官与写手**不要用同一个模型**（自己看不出自己的腔调）。

### ③ 段落级重写（核心环节）

**只重写疑似段落，不全文重写**——保结构保事实。对每个疑似段落调 Gemini：

```
prompt 模板：
你是中文个人技术博客博主。重写下面这一个段落，让它像真人写的。
[上下文：段落前后各一段，供衔接]
[待改段落]
要求：
- 只改表达，事实、数字、术语、代码一个不许动
- 长短句悬殊化：关键判断可拆成短句，叙述允许长句
- 删掉 AI 腔（[该段落的具体问题：禁语/加粗/句长均匀...]）
- 禁止出现：这意味着/值得注意的是/不难发现/综上所述/先说结论/让我们
输出：直接给改写后的段落，不要解释。
```

调用方式同 tech-blog-writer（gemini-2.5-flash，代理 7897，段落级请求小可连发但间隔 ≥20s）。

### ④ 事实 diff 质检（每轮必做，python）

```python
# 改写前后各提取数字序列与术语集合，比对：
import re
nums = lambda s: re.findall(r'\d+(?:\.\d+)?%?(?:×\d+)?', s)
terms = lambda s: set(re.findall(r'[A-Za-z][\w.-]{2,}', s))
# 要求：数字序列完全一致；术语集合只减不增（不许冒新名词）
```

不一致 → 该段落回滚重写；两轮仍不一致 → 该段落保持原文（宁可留 AI 味不编事实）。

### ⑤ 收敛判断

连续两轮 detect.py 疑似项不再下降 → 停，进入终审。最多 3 轮——更多轮次的经验教训：过拟合检测器，文字开始变怪。

### ⑥ 人终审（不可省）

输出三件套：改写后全文 + Before/After 段落对照（detect.py 加 `--json` 可程序化生成对照）+ 本轮检测分变化。人说不行的段落，记下「为什么觉得 AI」的具体反馈，作为下一篇文章 ③ 环节 prompt 的追加规则——**循环的学习闭环在人这里，不在检测器里**。

## 外部检测器（可选人工环节）

统计层之外想加外部视角时，手动粘贴到：腾讯朱雀（中文最强，分句染色）/ GPTZero（句级高亮）。用法定位：**改写前测一次、终审前测一次做对比**，不作为循环退出条件（防止过拟合）。这些工具对中文博客体均有误报，分数只看趋势不看绝对值。

## 与其他 skill 的分工

- 生成新文章 → `tech-blog-writer`（素材包流水线）
- 本 skill 处理**已有文章**的去 AI 味（别人写的旧文、自己不满意的文章）
- 段落改写的红线参照 `shuorenhua`（保真约束）、模式参照 `humanizer-zh`（31 条字句模式）
